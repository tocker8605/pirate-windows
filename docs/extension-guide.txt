확장을 위한 코드 구조 (2026-11-22 정리)

스테이지
- data/stages.json이 스테이지 수, 음악, 배경 경로/구획 이름, 초기 스크롤, 구름, 원작 배경 지원 여부를 관리합니다.
- stage01~05.json은 등장 타임라인입니다. stages.json은 타임라인 파일이 아닙니다.
- ID는 1부터 연속입니다. 보스러시 대상은 앞부분의 연속된 스테이지만 지정할 수 있습니다.
- 4면의 지구/우주/월면/지하 구성은 layout: earth_lunar, 나머지는 three_region입니다.
- boss_rush_initial은 해당 모드에서만 초기 스크롤 값을 덮어씁니다.

기체 좌표와 그림
- actor.pos는 이동/발사/충돌의 기존 논리 좌표입니다. 리팩토링 때문에 그 기준을 바꾸지 않았습니다.
- scripts/entity_geometry.gd가 실제 이미지 사각형, 표시 중심, 반전, 회전, 힌지 좌표를 계산합니다.
- visual.anchor: top_left / top_center / hinge. hinge는 그림 안의 hinge_uv 위치를 actor.pos에 맞춥니다.
- visual.flip_h, rotation_radians, painted_size로 기존 개별 스프라이트 보정을 데이터에 둡니다.
- 충돌 범위 collision은 actor.pos 기준입니다. 이미지 교체가 피격영역이나 발사점을 자동으로 바꾸지 않습니다.
- sprite_path는 개별 PNG입니다. sprite_region은 필요할 때 투명 여백을 자르는 [x,y,width,height]입니다.
- sprite_fit은 stretch / contain입니다. 힌지와 비율 맞춤도 같은 공통 계산을 사용합니다.
- entity_textures.gd는 요청받은 이미지만 지연 로드합니다. 포대 하나 때문에 보스 이미지 전체를 먼저 읽지 않습니다.

서로 독립적인 동작 설정
- visual.layer: air / floor. visual.order는 바닥 보스 파츠 사이의 표시 순서입니다.
- movement_mode: pattern / stationary / scenery. 현재 scenery는 ground_turret의 실제 배경 이동량을 따릅니다.
- boss_scroll.stop_on_spawn은 등장 시 배경 정지 여부, defeat_speed는 본체 파괴 후 목표 스크롤 속도입니다.
- 지상 포대의 해치/잔해 이미지 경로와 영역, 발사 중심은 ground_turret 안에서 지정합니다.
- 해치 개폐, 노출 전 무적, 잔해 유지 규칙은 ground_turret.gd와 ground_art.gd가 맡습니다.

발사
- fire_channels의 interval_seconds와 gate가 발사 주기/조건을 정합니다. attack_timer.gd는 기체별 시간을 유지합니다.
- 각 채널의 volley는 탄의 형상/포구/속도를 지정합니다. projectile_volley.gd는 적 ID 대신 이름 붙은 형상을 계산합니다.
- aimed, fixed, fixed_pair, random 등 공통 형상은 데이터만 추가해 재사용할 수 있습니다.
- 기존 특수 궤적도 형상 이름으로 분리했으며 속도 값은 모두 px/s입니다. 30ms 왕복 단위 변환은 제거했습니다.
- 조준 기준은 변경하지 않았습니다. 기존 aimed 채널은 적/플레이어의 논리 좌표, shoulder_fan과 대형 조준팬은 실제 콕핏 기준입니다.
- 독립 타이머의 잔여 시간, 조건 해제 시 초기화, 첫 발사 대기, 탄의 순서는 유지합니다.

난수
- random.gd는 전투 난수입니다. 새로운 시각효과는 visual_random.gd의 독립 스트림을 사용합니다.
- legacy_event는 과거 폭발이 소비하던 전투 난수 한 칸을 예약하고 첫 시각 표본도 보존합니다.
- 그 이벤트에서 추가로 뽑는 난수는 전투 순서를 바꾸지 않습니다.
- reserve_transition_history는 제거된 로딩 이미지 추첨의 한 칸을 예약합니다. 마지막 스테이지도 동일합니다.
- 이 호환 예약은 기존 플레이 결과를 보존하기 위한 경계입니다. 새 효과에서는 추가하지 않습니다.

검증
- tests/refactor_equivalence.gd는 이번 변경 직전 기록과 발사 틱/위치/탄종/속도/전투 난수를 대조합니다.
- attacks_before_structure_refactor.json은 수정 전 실행에서 기록했습니다. 수정 후 결과로 기대값을 덮어쓰지 않습니다.
- 과거 v24.43 이동 리플레이 JSON은 보관했고 원래 검사 코드는 fixtures/refactor_equivalence_v24_43.gd.txt에 남겼습니다.
- tests/structure_extensibility.gd는 설정 분리, 새 스테이지, 힌지, 지연 로딩, 난수 독립성, 1/7번 발사 주기를 검사합니다.
- tools/test.ps1은 일반 검사, -Render는 GPU 렌더링 검사까지 실행합니다.

5면 보스 바닥 장식과 특수 포대
- 본체95의 floor_decoration.asset / size / offset으로 전선다발을 지정합니다.
- 전선은 실제 본체 표시 중심을 기준으로240x240이며, 별도 HP/충돌/점수가 없는 바닥 장식입니다.
- 배경 다음, 잔해/포대/보스 본체보다 먼저 그립니다. 본체가 생기면 표시되고 스테이지 전환 시 함께 사라집니다.
- 특수 기관포145, 특수 에너지포146은 role: part인 ground_turret입니다.
- 특수145/146은 HP800이며 점수/해치/잔해는 일반 포대를 재사용합니다. 일반51/52 HP는200입니다.
- 145는51과 같은0.24초 기관포 공격, 본체 HP1/3 이하에서 개방합니다.
- 52는0.48초에 중앙 큰 분홍탄(kind4), 좌우 작은 분홍탄(kind5)을8px 간격으로 나란히 발사합니다.
- 146은 같은3연탄을0.24초마다 발사하며8초에 한 바퀴씩 연속 회전하고, 본체 HP2/3 이하에서 개방합니다. 왼쪽 시계/오른쪽 반시계, 첫 방향은 아래입니다.
- stage05.json의82초 이벤트에145 두 기,146 두 기를 임시 배치했습니다. position은 포대 중심에서(-25,-25)인 기존 논리 좌표입니다.
- 특수 포대는 JSON position의X만 사용합니다. Y는145번 본체Y+150,146번 본체Y+300으로 추종합니다.
- 특수 포대의 boss_hatch 설정은 start_exposed보다 우선합니다. 본체 HP가 높으면 닫힘 상태이며, 기준 이하에서만 기존0.8초 전개를 재사용합니다. 닫히는 동안과 전개 중 무적, 완전 노출 후 공격/피격, 기체 충돌 없음, 파괴 후 잔해 유지입니다.
- 본체 파괴 시 다른 파츠처럼 자동 파괴되며 이 경우 파츠 점수는 없습니다.

포대 확장 필드: ground_turret.projectile_kinds는 포구별 탄종, parallel은8px 평행 대형, boss_hatch는 참조 본체ID/HP 비율, rotation은 첫 각도(initial_degrees)/한 바퀴 주기(period_seconds)입니다. 회전 방향은 생성 위치가 본체 중심의 왼쪽이면 시계방향, 오른쪽이면 반시계방향으로 고정됩니다.

보스러시5면: data/stage15.json. data/stages.json의5면 boss_rush_initial에서 background_y480, map_mode3을 지정하여 슈퍼컴퓨터 챔버부터 시작합니다. 본체·파츠 등장 시점과 배경 정지 시점은 stage15.json에서 각각 설정하며, 일반 포대와 정기 보급 편성은 없습니다. 5면 클리어 후 랭킹 입력 없이 타이틀로 복귀합니다.

보스러시는 본체 등장 시 스크롤을 강제로 정지하지 않습니다. stage15.json의 scroll 이벤트가 목표 속도를 결정합니다. speed0 이벤트 뒤에는 기존 감속률로 정지합니다(30px/s에서는 약0.135초). 5면은 일반/보스러시 모두 본체 Y좌표 조건으로 정지합니다.

5면 본체는 movement_mode: scenery로 바닥의 실제 이동량을 따릅니다. boss_scroll.stop_after_y: 25을 넘는 순간 한 번만 목표 속도를0으로 설정하고, 기존 감속률222.222px/s²로 정지합니다. stage15의15초 정지 이벤트는 제거했습니다. 감속 중에도 본체·부착 파츠·전선·포대는 바닥에 맞춰 이동합니다.

특수 포대145의 논리Y는 본체Y+150,146은 본체Y+300입니다. X는 타임라인 position의 값을 유지하며 본체X를 따라가지 않습니다. attachment.follow_x:false로 지정했고, 기존 팔·날개는 기존처럼 X/Y 부착값을 따릅니다.


5면 확장 이후 시뮬레이션 계약
- 게임의 고정 스텝은 Ground.begin_step(보스 HP 조건/회전 스냅샷) → Fire.advance_prepared(발사) → 배경/보스 이동 → Ground.finish_step(위치/해치 표시/조준) 순서입니다.
- 완전 전개 시점과 첫 발의 관계를 보존하기 위해 해치 진행은 기존처럼 발사 이후에 갱신합니다. 발사 함수와 렌더러는 해치/회전/위치를 진행하지 않습니다.
- 도구에서 한 기체의 공격을 독립 시뮬레이션할 때는 Fire.advance를 사용합니다. 이 함수는 begin_step과 advance_prepared를 순서대로 수행합니다. 같은 스텝에서 두 진입점을 중복 호출하지 않습니다.
- 부착 위치는 entity_attachment.gd가 결정합니다. follow_y인 특수 포대는 배경 Y 계산을 거친 뒤 덮어쓰지 않고 처음부터 본체 Y를 사용합니다. 일반 포대와 잔해는 scenery_motion.gd의 실제 배경 이동량을 사용합니다.
- player_projectile_geometry.gd가 저장된 탄환/플레이어 좌표를 화면상 탄 중심/레이저 중심으로 변환합니다. collision.shot_bounds와 beam_bounds는 모두 적 논리 위치 기준의 로컬 범위이며 가장자리는 포함하지 않습니다. 적별 shot_offset은 제거했습니다. Y 판정도 기존 동작을 유지하도록 변환되어 있습니다.
- 특수 공격도 AttackTimer.periodic을 사용합니다. 조건 해제 시 부분 주기를 버리고, 주기 변경 시 초기화는 명시적으로 선택합니다. 1면 본체의 주먹 전멸 후 연사 전환 규칙을 유지합니다.
- HTML 매뉴얼의 적 목록/HP, 파일 표, 샘플 선택 목록, 내장 타임라인은 python tools/sync_timeline_manual.py로 갱신합니다. --check는 쓰기 없이 일치 여부를 검사합니다. tools/test.ps1의 manual_sync 검사도 원본 JSON과 내장 데이터 불일치를 감지합니다. _bak.json 등 백업은 제외합니다.
- tests/fixtures/expansion_before_refactor.json은 이번 정리 이전에 확보한 기준입니다. 수정된 코드의 결과로 기준 파일을 덮어써서 검사를 통과시키지 않습니다.
