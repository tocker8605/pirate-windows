확장을 위한 코드 구조 (2026-11-22 정리)

스테이지
- data/stages.json이 스테이지 수, 음악, 배경 경로/구획 이름, 초기 스크롤, 구름, 원작 배경 지원 여부를 관리합니다.
- stage01~05.json은 등장 타임라인입니다. stages.json은 타임라인 파일이 아닙니다.
- ID는 1부터 연속입니다. 보스러시 대상은 앞부분의 연속된 스테이지만 지정할 수 있습니다.
- 4면의 지구/우주/월면/지하 구성은 layout: earth_lunar, 나머지는 three_region입니다.
- boss_rush_initial은 해당 모드에서만 초기 스크롤 값을 덮어씁니다.

기체 좌표와 그림
- actor.pos는 이동/발사/충돌의 기존 논리 좌표입니다. 리팩토링 때문에 그 기준을 바꾸지 않았습니다.
- scripts/entity_geometry.gd가 실제 이미지 사각형, 표시 중심, 반전, 회전, 힌지 좌표를 계산합니다.
- visual.anchor: top_left / top_center / hinge. hinge는 그림 안의 hinge_uv 위치를 actor.pos에 맞춥니다.
- visual.flip_h, rotation_radians, painted_size로 기존 개별 스프라이트 보정을 데이터에 둡니다.
- 충돌 범위 collision은 actor.pos 기준입니다. 이미지 교체가 피격영역이나 발사점을 자동으로 바꾸지 않습니다.
- sprite_path는 개별 PNG입니다. sprite_region은 필요할 때 투명 여백을 자르는 [x,y,width,height]입니다.
- sprite_fit은 stretch / contain입니다. 힌지와 비율 맞춤도 같은 공통 계산을 사용합니다.
- entity_textures.gd는 요청받은 이미지만 지연 로드합니다. 포대 하나 때문에 보스 이미지 전체를 먼저 읽지 않습니다.

서로 독립적인 동작 설정
- visual.layer: air / floor. visual.order는 바닥 보스 파츠 사이의 표시 순서입니다.
- movement_mode: pattern / stationary / scenery. 현재 scenery는 ground_turret의 실제 배경 이동량을 따릅니다.
- boss_scroll.stop_on_spawn은 등장 시 배경 정지 여부, defeat_speed는 본체 파괴 후 목표 스크롤 속도입니다.
- 지상 포대의 해치/잔해 이미지 경로와 영역, 발사 중심은 ground_turret 안에서 지정합니다.
- 해치 개폐, 노출 전 무적, 잔해 유지 규칙은 ground_turret.gd와 ground_art.gd가 맡습니다.

발사
- fire_channels의 interval_seconds와 gate가 발사 주기/조건을 정합니다. attack_timer.gd는 기체별 시간을 유지합니다.
- 각 채널의 volley는 탄의 형상/포구/속도를 지정합니다. projectile_volley.gd는 적 ID 대신 이름 붙은 형상을 계산합니다.

- 기존 특수 궤적도 형상 이름으로 분리했으며 속도 값은 모두 px/s입니다. 30ms 왕복 단위 변환은 제거했습니다.
- 조준 기준은 변경하지 않았습니다. 기존 aimed 채널은 적/플레이어의 논리 좌표, shoulder_fan과 대형 조준팬은 실제 콕핏 기준입니다.
- 독립 타이머의 잔여 시간, 조건 해제 시 초기화, 첫 발사 대기, 탄의 순서는 유지합니다.

난수

5면 확장 이후 시뮬레이션 계약
- 게임의 고정 스텝은 Ground.begin_step(보스 HP 조건/회전 스냅샷) → Fire.advance_prepared(발사) → 배경/보스 이동 → Ground.finish_step(위치/해치 표시/조준) 순서입니다.
- 완전 전개 시점과 첫 발의 관계를 보존하기 위해 해치 진행은 기존처럼 발사 이후에 갱신합니다. 발사 함수와 렌더러는 해치/회전/위치를 진행하지 않습니다.
- 도구에서 한 기체의 공격을 독립 시뮬레이션할 때는 Fire.advance를 사용합니다. 이 함수는 begin_step과 advance_prepared를 순서대로 수행합니다. 같은 스텝에서 두 진입점을 중복 호출하지 않습니다.
- 부착 위치는 entity_attachment.gd가 결정합니다. follow_y인 특수 포대는 배경 Y 계산을 거친 뒤 덮어쓰지 않고 처음부터 본체 Y를 사용합니다. 일반 포대와 잔해는 scenery_motion.gd의 실제 배경 이동량을 사용합니다.
- player_projectile_geometry.gd가 저장된 탄환/플레이어 좌표를 화면상 탄 중심/레이저 중심으로 변환합니다. collision.shot_bounds와 beam_bounds는 모두 적 논리 위치 기준의 로컬 범위이며 가장자리는 포함하지 않습니다. 적별 shot_offset은 제거했습니다. Y 판정도 기존 동작을 유지하도록 변환되어 있습니다.
- 특수 공격도 AttackTimer.periodic을 사용합니다. 조건 해제 시 부분 주기를 버리고, 주기 변경 시 초기화는 명시적으로 선택합니다. 1면 본체의 주먹 전멸 후 연사 전환 규칙을 유지합니다.
- HTML 매뉴얼의 적 목록/HP, 파일 표, 샘플 선택 목록, 내장 타임라인은 python tools/sync_timeline_manual.py로 갱신합니다. --check는 쓰기 없이 일치 여부를 검사합니다. tools/test.ps1의 manual_sync 검사도 원본 JSON과 내장 데이터 불일치를 감지합니다. _bak.json 등 백업은 제외합니다.
- tests/fixtures/expansion_before_refactor.json은 이번 정리 이전에 확보한 기준입니다. 수정된 코드의 결과로 기준 파일을 덮어써서 검사를 통과시키지 않습니다.


회전 파츠와 충돌 확장
- pose_motion: {type:"swing", period_seconds:6, angle_degrees:15, pivot:[0,0]}으로 물리 판정과 연결된 왕복 회전을 지정합니다. 음수 각도는 반시계 방향입니다. 각도는0에서 최대값까지 주기의 절반 동안 이동하고 나머지 절반 동안0으로 돌아옵니다. 코사인 보간으로 양 끝에서 부드럽게 방향을 바꿉니다.
- pivot은 적 논리 위치 기준의 로컬 회전 중심입니다. 143/144의 논리 위치는 힌지이므로 pivot:[0,0]을 사용합니다. 좌우 반전은 기존 스프라이트 배치에만 적용되며, 로컬 피격 범위/포구/연기 오프셋은 이미 좌우별로 정의되어 있습니다.
- entity_pose_motion.gd는 시뮬레이션 시간에 따라 각도를 갱신합니다. game.gd의 발사 전 단계에서 한 번 진행하며, 도구에서는 Fire.advance를 사용합니다. 발사 시에는 정확한 이벤트 시각의 각도를 샘플링하므로 큰 스텝에서도 여러 탄이 한 위치에서 겹쳐 나오지 않습니다.
- entity_geometry.gd의 local_frame/world_point/local_point/sprite_transform이 공통 좌표 변환 API입니다. 특정 적 ID에 의존하지 않습니다. 회전 없는 개체는 기존 좌표 덧셈/뺄셈을 사용하여 행렬 연산을 피합니다.
- collision_geometry.gd는 회전·이동된 로컬 사각형에 대한 점/원/광선 검사를 제공합니다. 현재는 강체 변환(이동+회전)을 대상으로 하며 비균등 확대/축소는 지원 계약에 포함하지 않습니다. 일반탄은 점, 기체 접촉은 원, 레이저는 위쪽 반직선으로 검사합니다.
- pose_motion 사용 시 collision.beam_rect:[left,top,right,bottom]이 필요합니다. 회전된 모양을 둘러싼 큰 축 정렬 사각형으로 대체하지 않고 실제 로컬 사각형과 광선의 교차를 검사합니다. 기존 비회전 개체의 beam_bounds 동작은 유지합니다.
- 미사일 포구와 연기 발생점은 같은 좌표 변환을 사용합니다. 발사 이후 미사일의 속도/가속, 이미 발생한 연기의 흐름은 월드 좌표를 유지합니다. 연기 전체를 날개에 붙여 회전시키지 않습니다.

범위 왕복 회전과 탄 묶음 확장
- pose_motion.type:swing_range는 min_degrees/max_degrees/initial_degrees/initial_direction(1또는-1)을 사용합니다. period_seconds가 전체 왕복 주기입니다. 처음부터 특정 끝 각도로 순간 이동하지 않고 지정한 초기 각도와 방향으로 시작합니다.
- expanding_ring 발사형은 count개 탄환을 start_radius의 원주에 배치하고 포구 방향으로 speed의 공통 속도를 줍니다. end_radius/expand_seconds로 반경 변화를 지정합니다. count6이면 육각형입니다.
- projectile_formation.gd는 각 탄환의 추가 방사 변위만 계산합니다. 중앙 진행 속도와 방사 확장을 분리하므로 탄환 하나가 사라져도 나머지 탄에 영향이 없고, 발사 후 기체의 이동/회전을 따라가지 않습니다. BulletPool은 선택적 formation 메타데이터를 각 탄에 독립 복사합니다.


탄환 이동과 고정 설정의 실행 준비
- projectile_motion.gd가 적탄의 가속, 기본 이동, 선택적 대형 확장을 순서대로 처리합니다. combat_actions.gd는 이동 완료 후 화면 이탈/보호막/피격/점수를 처리합니다. 가속 후 이동, 이동 후 확장이라는 기존 순서를 유지합니다.
- expanding_ring의 start_radius/end_radius/expand_seconds는 카탈로그 로딩 시 읽기 전용 formation_profile로 준비됩니다. 각 탄환은 이 고정 설정을 공유하고 direction/age만 독립적으로 가집니다. BulletPool은 상태만 얕게 복사하므로 원본 발사 데이터와 다른 탄환의 경과 시간이 섞이지 않습니다. 새로 도입하는 변경 가능한 중첩 메타데이터는 같은 방식으로 명시적으로 복사해야 합니다.
- pose_curve.gd는 pose_motion을 카탈로그 로딩 시 실행용 pose_curve로 변환합니다. 범위 회전의 중심각/진폭/시작 위상, 단순 왕복의 라디안 각도와 회전 중심을 미리 계산합니다. 매 프레임 및 발사 시각 샘플링에서는 준비된 곡선과 경과 시간만 사용합니다.
- JSON은 기존 pose_motion/volley 필드로 계속 편집합니다. pose_curve와 formation_profile은 실행 중에만 존재하는 파생 값이므로 JSON에 추가하지 않습니다. 도구에서 각도만 확인하려면 Motion.angle(Catalog.definition(id).pose_curve,seconds)를 사용합니다.
- tests/fixtures/motion_before_refactor.json은 이번 이동/고정값 분리 이전에 기록한 회전·발사·물리 결과입니다. 공유 설정/상태 독립성은 shared_motion_state, 수치 동등성은 motion_refactor_equivalence에서 검증합니다.


공통 지속형 레이저 공격
- enemies.json의 beam_attacks는 일반 탄환 발사 채널과 분리된 지속형 공격입니다. 각 기체에 name이 다른 공격을 여러 개 지정할 수 있습니다. gate는 immediate 또는 scroll_stopped이며, 후자는 처음 스크롤이 멈춘 시점에 시작하여 이후 독립 주기를 유지합니다.
- origin은 기체 로컬 발사점, period_seconds/telegraph_seconds/active_seconds는 전체/예고/공격 시간입니다. 나머지 시간은 쿨타임이며 선분을 생성하지 않습니다. beams 배열의 from_degrees/to_degrees는12시 기준이며 양수가 시계 방향입니다. 각도는 최단 경로로 보정하지 않고 명시한 부호와 범위를 그대로 보간합니다.
- width는 실제 공격 폭, telegraph_width는 예고 폭입니다. color와 damage_scale을 지정합니다. 표시와 피격 판정이 beam_attack.gd의 동일한 선분/폭 스냅샷을 사용합니다. 예고 선분은 damaging:false라서 판정에 들어가지 않습니다.
- beam_attack_schema.gd는 설정 검증, beam_attack.gd는 기체별 시작 조건/시간/선분 생성, enemy_beam_art.gd는 표시를 담당합니다. collision_geometry.gd의 circle_segment_hits는 두께가 있는 유한 선분과 원의 충돌 검사로 다른 지속형 공격에서도 사용할 수 있습니다. combat_actions.gd가 기존 난이도 대미지와 무적시간을 적용합니다.
- 보스 사망 즉시 목록을 비우며, 이미 만들어진 선분도 소유자의 생존 여부를 검사합니다. 스테이지 로딩 시 상태를 초기화하고, 일시정지 중에는 시뮬레이션이 진행되지 않습니다. 미래의 다른 적/파츠도 같은 데이터와 모듈을 사용할 수 있으며,5면 ID 분기는 없습니다.

- BeamMuzzleEffect.emitters는 여러 광선이 같은 소유자/공격 이름에서 출발할 때 하나의 발사점으로 묶습니다. CombatVFX는 전용 발사점 효과 모듈을 사용해 예고 단계의 작은 충전 효과와 발사 단계의 강화된 코어/스파크를 구분합니다. 쿨타임/사망 시에는 생성하지 않으며, 기존 표시 전용 난수와 파티클 예산을 사용합니다. 프레임 지연 후 누적 생성하지 않습니다.

- width_transition_seconds는 표시 폭의 생성/소멸 시간입니다. beam_attack이 visual_width만 보간하고, width는 공격 중 고정되어 피격 판정이 달라지지 않습니다. 현재1→5→1px 전환 시간은 각각0.2초입니다.
- 레이저 관련 파티클은 전용 표시 레이어3으로 분리되어 레이저 본체 뒤에 가려지지 않습니다. 단계2의 중심 코어는 후속 코어가 생성될 때까지 불투명도를 유지하여 V자 이음 부분을 덮습니다. 기존 연기/탄환/일반 파티클의 상대 순서는 유지합니다.


레이저 시각효과 모듈과 실행용 설정
- beam_muzzle_effect.gd가 발사점 묶기, CHARGE/FIRING 단계별 생성 주기, 코어 표시를 담당합니다. 인스턴스별 시계만 보유하며 공통 CombatVFX의 파티클 저장소/예산/표시용 난수를 그대로 사용합니다. 난수 호출 순서와 레이저 위에 코어를 그리는 순서를 유지합니다.
- particle_layers.gd의 Layer.ALL/SMOKE/GENERAL/BEAM_FOREGROUND로 표시 그룹을 구분합니다. 각 비연기 배치를 한 번 선택한 뒤 글로우/스파크를 순서대로 그리고 코어를 마지막에 그립니다. 기존 정수값은 그대로여서 기존 도구 호출도 유지됩니다.
- beam_profile.gd는 카탈로그 로딩 시 JSON의 beam_attacks를 읽기 전용 beam_profiles로 변환합니다. origin은 Vector2, color는 Color, 회전 시작/끝은 라디안으로 준비됩니다. beam_attack.gd는 실행용 설정으로 시간/기하/피격만 처리하고 시각효과의 발사점 묶기는 담당하지 않습니다.
- JSON에는 기존 beam_attacks를 그대로 편집합니다. 독립 도구가 원시 설정으로 샘플을 만들려면 BeamProfile.prepare(raw_spec) 이후 BeamAttack.sample(owner,prepared_spec,time)를 호출합니다. 카탈로그 설정을 사용하면 definition.beam_profiles에 이미 준비되어 있습니다.
- tests/fixtures/beam_before_visual_refactor.json은 이번 정리 이전에 기록한 기준입니다. beam_visual_equivalence가 레이저와 파티클 생성/상태/난수 순서를 대조하고, beam_refactor_contracts가 설정 불변성과 레이어·예산·시계 독립성을 검사합니다.

- aimed 발사 설정은 aim_from_muzzle:true로 지정하면 각 포구에서 주인공 콕핏을 직접 조준합니다. 기본값 false는 기존 기체 기준 조준을 유지합니다. rotating 발사는 radial_angles[channel.name]에 다음 발사 각도를 저장하므로 같은 기체의 여러 포구도 회전 위상이 독립적입니다.

- beam_attacks의 health_phases는 HP비율별 경로 목록입니다. 가장 낮은 해당 at_or_below_ratio를 선택하며, continuous:true는 최초 예측선 후 지속 발사합니다. 선택적 swing.amplitude_degrees/period_seconds는 두 광선의 간격을 유지한 공통 왕복 회전을 지정합니다. 경로는 주기 시작에 확정하고 지속 단계는 기존15초 주기와 독립된 경과 시간을 유지합니다.

- laser_contacts는 월드 좌표입니다. 회전 힌지 파츠의 레이저 피격 이펙트는 기존 피격 판정을 통과한 후 실제 sprite_region/contain/mirror/pose로 변환한 그림 경계와의 교차점에 발생합니다. 피격 사각형의 여유 영역은 유지하며, 시각 경계가 교차하지 않는 경우 피격 경계를 사용합니다. 파괴 이펙트는 hinge 기준점 대신 같은 스프라이트 변환의 중심을 사용합니다. 기존 비힌지 적의 이펙트 배치는 유지합니다.

- beam_timeline.gd는 시작 게이트, HP 단계 선택, 주기별 경로 확정, 지속 발사의 시간 기준과 예측/발사/휴식 구간을 담당합니다. beam_attack.gd는 준비된 시간과 패턴으로 선분·피격 폭·표시 폭을 계산합니다.
- beam_profile.gd는 기본 패턴(default_phase)과 HP별 패턴(health_phases)을 동일 필드의 읽기 전용 구조로 준비합니다. authored JSON 구조는 그대로이며 기본값 처리는 로딩 시 한 번만 수행합니다.
- stage5_continuous_beam은 지속 레이저, stage5_autocannon은 기관포 회전/발사 검사를 담당합니다. beam_timing_equivalence는 이번 분리 이전의 실행 결과를 보관한 fixture와 시간·선분·폭·파티클·포대 결과를 비교합니다.

- stage_resources.gd는 검증·정렬된 타임라인의 spawn 정의에서 각 스테이지의 리소스 목록을 수집합니다. StageSession은 play_stage 전에 렌더러의 실제 텍스처/아틀라스 캐시와 음악 캐시, 보스 HUD/경고 이미지를 준비합니다. 스테이지 번호별 분기 없이 일반/보스러시에 공통 적용되며 이벤트 소비·배치·난수·공격 타이머는 변경하지 않습니다.
- EntityTextures.prepare_definition은 카탈로그에 지정된 본체/파츠, 지상 포대 해치/잔해와 바닥 장식 에셋을 준비합니다. Audio.prepare_music은 트랙을 재생하지 않고 보관하며 stop 후에도 재사용합니다. stage_resource_loading 검사는 모든 스테이지·모드와 원본 스프라이트 옵션의 캐시 준비, 등장 시 추가 로딩 없음, 음악 시점을 검증합니다.
- 보스 로딩 측정: Godot --headless --audio-driver Dummy --path . --script tools/profile_boss_loading.gd. 출력은 스테이지 초기화 및 보스 에셋 접근의 CPU 경과시간이며 GPU 프레임 시간 전체를 의미하지 않습니다.

- 주인공 X레이저의 대미지/피격 파티클/공통 beam_hits API는 Combat.beam_contact의 최종 월드 피격 지점Y가-50 이상일 때에만 허용합니다. 회전 파츠는 기존 스프라이트 경계 교차점, 나머지는 기존 역할별 피격 연출 지점을 사용하며 주인공 레이저 이외의 공격 판정은 유지합니다.
