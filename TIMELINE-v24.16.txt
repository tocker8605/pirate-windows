이제 실제 초 단위입니다.게임 시뮬레이션 시간이며 일시정지 중 멈춥니다.
{
  "schema_version": 2,
  "time_unit": "seconds",
  "events": [
    {"at": 2.75, "action": "spawn", "definition_id": 1,
     "position": [50,-50], "pattern": 1011}
  ]
}
at=2.75는2초750ms입니다.1ms는0.001로 표현합니다.
실제 처리는60Hz시뮬레이션에서 예약 시각을 지난 첫 틱에 실행됩니다.
과거의 strict-after 경계 동작도 보존했습니다.

기존 이벤트 이동:
  이전at1 -> 새at0.9초
  이전at3 -> 새at2.7초
  이전at10 -> 새at9초
  이전at116 -> 새at104.4초
모든 at를 정확히0.9배로 변환했으므로 기존 등장 시점과 순서가 유지됩니다.
앞으로 새로 작성할 때는 at10을10초로 해석하면 됩니다.

타임라인 개수 상한은 없습니다.동적배열과 다음이벤트 커서를 사용합니다.
처리량은 현재 틱까지 도래한 이벤트 수에 비례하며 이미 처리한 항목을 다시 탐색하지 않습니다.
이번 검사에서1000동시생성과 후속 제어를 포함한1001이벤트를 처리했습니다.
시간순으로 저장해야 하며 같은시각 이벤트는 JSON순서대로 실행됩니다.
