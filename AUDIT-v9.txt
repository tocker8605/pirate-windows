Pirate II v9 — 동시 노출 제한 해제와 활성 객체 관리 개선

원본/이전 상태 확인
  VB6 frmtmrs.frm은 적을 For enect=0 To 29, 적탄/아이템을 For ewct=0 To 199로 처리합니다.
  선언 en(30), ew(200)의 배열 상한과 실제 사용 루프는 구분해야 합니다.
  일부 발사 종류는 탄환 커서를 145~148에서 먼저 되돌려 더 작은 영역을 사용했습니다.
  v8까지는 원본 재현을 위해 이 슬롯 점유·건너뛰기·덮어쓰기까지 유지했습니다.
  당시 포팅 코드는 적탄 생성 시 배열 선형 탐색과 filter 재생성,
  매 틱 적/아이템 정렬과 적 렌더링용 전체 복사를 사용했습니다.

새 자료구조
  entity_store.gd: ID 해시맵 + 생성 순서의 활성 양방향 연결 목록.
  연결은 다음 노드 참조와 이전 노드 ID를 사용하여 순환 참조를 피합니다.
  적·적탄·아이템은 각각 독립된 store를 소유합니다.
  생성·ID 조회·ID 삭제: 평균 O(1), 전체 순회/비우기: O(활성 객체 수).
  고정 크기 배열, 빈 슬롯 찾기, 커서 래핑, 점유로 인한 생성 누락을 제거했습니다.
  ID는 삭제/스테이지 전환 뒤에도 재사용하지 않아 오래된 ID가 다른 객체를 가리키지 않습니다.
  생성 순서가 안정적이므로 매 틱 정렬이 필요 없습니다.
  현재 노드를 순회 도중 제거해도 다음 노드를 건너뛰지 않습니다.
  clear에서는 긴 참조 연결을 반복문으로 끊어 고밀도 상태의 재귀 해제를 피합니다.
  snapshot/at은 테스트·진단용이며 실제 게임 루프에서는 사용하지 않습니다.
  해시맵과 노드의 객체별 메모리 비용은 있습니다. 무제한 메모리나 모든 기기에서 일정 FPS를 뜻하지 않습니다.

게임 적용
  적 30기, 적탄 200슬롯의 하드 제한을 제거했습니다.
  각 적/보스는 기존 좌표·위상·벡터 수식으로 계산된 탄막 전체를 발사합니다.
  기존 탄환을 덮어쓰거나, 슬롯 점유 때문에 적 이벤트를 버리지 않습니다.
  아이템도 탄환과 독립시켜 3슬롯 덮어쓰기·탄환 차단을 제거했습니다.
  적의 매 틱 정렬과 렌더링용 Dictionary 전체 복사를 제거했습니다.
  화면 밖/파괴 객체를 ID로 연결 해제하여 배열 filter 재생성을 없앴습니다.
  다른 적이 생성되어 기존 폭발이 지워지던 슬롯 재사용 연출도 제거했습니다.
  원본 이벤트 시각과 읽기 1회당 5개 actor 처리 주기는 유지합니다.
  이것은 동시 생존 제한과 다른 규칙이며 이벤트를 누락하지 않습니다.

의도한 동작 차이
  종전에는 밀집 상황에서 생략/덮어쓰던 적과 탄환이 이제 정상 생성됩니다.
  따라서 해당 구간의 탄막 밀도와 난수 소비 순서, 난이도는 v8/원작과 달라질 수 있습니다.
  발사 시각·좌표별 발사 수식·궤적·가속·피해량·판정·아이템 효과는 변경하지 않았습니다.
  VB 난수 수식과 발사 한 묶음 내 난수 소비 순서는 유지하며 슬롯에 의한 억제만 제거했습니다.
  파괴된 적의 1프레임 렌더 복사 대신 현재 활성 적과 v8 파티클 폭발을 직접 표시합니다.
  아군 사격의 별도 50슬롯 구조는 이번 변경 범위가 아닙니다.
  v8의 1500개 시각 입자 상한은 보조 연출용입니다. 적탄 개수나 탄환 본체 렌더링을 제한하지 않습니다.

검증과 측정
  전체 421개 검사를 구성했습니다. 최종 결과는 VALIDATION.txt를 참고하십시오.
  기존 슬롯 재현 검사 중 점유 억제/덮어쓰기를 검사하던 항목은 새 요구에 맞춰
  고밀도에서 전체 생성·기존 객체 보존·아이템 독립을 검사하도록 교체했습니다.
  적 150개 이벤트 처리, 적 256기의 동시 발사, 적탄 6000개의 이동/화면 밖 삭제,
  자료구조 10000개 등록/삭제와 중첩 순회, 오래된 ID, 일시정지/전환을 검사합니다.
  로컬 측정: 6000발 생성 약21.8ms, 적탄 갱신 5회 약110.9ms(회당22.2ms).
  이 수치는 해당 PC의 headless 게임 로직 측정이며 파티클·그리기·전체 프레임 비용을 포함하지 않습니다.
  별도 삽입 모델 비교(n=2000): 매번 탐색+filter 약487.6ms, 새 ID store 약5.3ms.
  모델 비교는 고유 ID를 계속 추가하는 상황이며 실제 v8의 200슬롯 제한 실행이나 FPS 비교가 아닙니다.
  새 실행본의 밀집 장면과 1~4스테이지 자동 진행도 확인합니다.

보존 및 형상관리
  원본 VB6 폴더와 기존 배포 ZIP을 수정하지 않았습니다.
  v8 파티클 변경 및 이번 v9 변경은 모두 로컬 수정 상태이며 커밋·푸시하지 않습니다.
